# 세션 회수와 출력 확정

## 경쟁 송신자는 상태를 건드리지 않는다

세션 소유자가 살아 있을 때 다른 PID의 `ACQUIRE`는 `BUSY`를 받는다. 다른
PID의 데이터 시그널은 비트 수, 현재 바이트와 순번을 바꾸지 않으며 ACK도 받지
않는다.

```c
if (g_client_pid == 0 || g_client_pid != event->sender)
	return (0);
```

거절 경로에서 기존 상태를 초기화하면 정상 송신자의 메시지가 조용히 손상된다.
`tests/session_ownership.sh`는 예약을 유지한 프로세스가 살아 있는 동안 두 번째
클라이언트가 실패하고 서버 출력이 한 바이트도 바뀌지 않는지 비교한다.

## 죽은 소유자의 부분 상태를 닫는다

새 예약이 왔을 때 기존 PID가 `ESRCH`로 사라진 것이 확인되면 비트 조립 상태를
비운다. 일반 바이트를 이미 출력해 줄이 시작됐다면 줄바꿈을 먼저 쓴다.

```c
if (kill(g_client_pid, 0) == -1 && errno == ESRCH)
{
	if (reset_session(1) == -1)
		return (-1);
}
```

이 줄바꿈이 실패하면 새 소유자에게 READY를 보내지 않는다. 반쯤 열린 줄을 닫지
못했는데 다음 메시지를 같은 줄에 이어 붙이는 상황을 막는다.

살아 있지만 `SIGSTOP` 상태인 프로세스는 자동 회수하지 않는다. 생존 확인만으로 장기 정지를 구분할 수 없기 때문이다. 운영 서비스라면 세션 lease와 갱신 정책이 추가로 필요하다.

## ACK는 외부 효과가 끝난 뒤 보낸다

바이트 출력이 짧게 끝나면 남은 부분을 이어 쓰고, `EINTR`이면 같은 구간을 재시도한다. `EPIPE`나 0바이트 쓰기처럼 복구할 수 없는 결과에서는 ACK를 차단한다. 확인 응답을 먼저 보내고 출력하면 클라이언트는 서버가 보존하지 못한 바이트를 성공으로 판단한다.

NUL 바이트의 줄바꿈도 메시지 완료 효과이므로 쓰기 성공 뒤에만 세션을 초기화한다.
`process_bit`은 완성된 바이트를 `flush_byte`로 내보낸 뒤에 순번을 증가시키고
ACK를 보낸다. 응답 전송 자체가 실패하면 현재 소유자의 부분 줄을 닫고 세션을
초기화한다.

`tests/output_failure.sh`는 본문 바이트, 종료 줄바꿈과 버려진 부분 줄을 닫는
줄바꿈에서 각각 `EPIPE`를 만들고 클라이언트가 성공하지 않는지 확인한다.
짧은 쓰기와 한 번의 `EINTR`는 전체 메시지가 보존되는 성공 사례로 분리한다.

```sh
make test
```

서버는 메시지를 메모리에 모아 원자적으로 출력하지 않는다. 바이트 단위로 stdout에
나가므로 서버나 클라이언트가 중간에 죽으면 부분 줄이 보일 수 있다. 세션 회수 시
줄바꿈은 경계를 복구할 뿐 이미 출력된 바이트를 되돌리지 않는다.
