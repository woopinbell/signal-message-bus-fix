# 이벤트 루프와 응답 검증

## 시그널 처리기에서는 사건만 넘긴다

시그널 처리기 안에서 문자열 조립, 소켓 송신, 형식 출력이나 메모리 할당을 수행하면 async-signal-safe 규칙을 위반하기 쉽다. 처리기는 `siginfo_t`의 송신자 PID와 시그널 번호를 작은 구조체로 만들어 nonblocking self-pipe에 쓴다.

구조체 크기는 `PIPE_BUF` 이하로 고정해 한 사건이 다른 쓰기와 섞이지 않게 한다. 파이프가 가득 차거나 쓰기가 실패하면 전역 overflow 표시를 세운다. 사건을 잃은 상태에서 계속 비트를 조립하면 손상된 메시지를 정상으로 확정할 수 있으므로 이벤트 루프는 이를 치명적 오류로 처리한다.

시그널 처리기는 진입 시 `errno`를 보관하고 복귀 전에 복원한다. 그렇지 않으면 메인 루프가 직전에 실패한 시스템 호출의 원인을 잘못 읽을 수 있다.

## 이벤트 루프가 상태를 바꾼다

메인 루프는 self-pipe와 세션 요청 소켓을 함께 기다린다. pipe에서 사건 구조체 전체를 읽은 뒤에만 세션 소유자 확인, 비트 조립, 출력과 ACK를 수행한다. 이 구조는 복잡한 로직을 일반 실행 문맥으로 옮겨 오류 처리와 테스트를 가능하게 한다.

`tests/masked_exec.c`는 `SIGUSR1`과 `SIGUSR2`를 막은 상태로 클라이언트를 실행한다. 클라이언트는 `kill`로 데이터 시그널을 보내고 datagram으로 응답을 기다리므로 이 마스크에서도 동작한다. 반면 서버는 상속받은 마스크에서 두 시그널을 명시적으로 해제하지 않는다. 부모가 막은 상태로 서버를 실행하면 처리기가 호출되지 않으며, 이 경로를 확인하는 자동 검사도 없다.

## 응답은 출처와 내용을 모두 확인한다

클라이언트는 datagram의 다음 항목을 모두 확인한다.

- 정확한 구조체 크기
- 서버 소켓 경로
- magic
- 서버 PID
- `READY` 또는 `ACK` 종류
- nonce 또는 비트 순번
- 성공 또는 busy 상태

버퍼를 구조체보다 한 바이트 크게 잡고 정확한 크기만 허용하므로, 큰 datagram이 정상 구조체 크기로 잘려 들어오는 일을 막는다. 조건이 맞지 않는 패킷은 버리되 전체 대기 기한은 유지한다.

## 상대 시간이 아니라 절대 기한을 쓴다

매번 고정 timeout으로 `pselect`를 다시 호출하면 잘못된 응답이나 `EINTR`가 올 때마다 총 대기 시간이 늘어난다. 시작할 때 `CLOCK_MONOTONIC` 기준 기한을 만들고 매 반복에서 남은 시간을 다시 계산한다. 시스템 시계가 조정되어도 단조 시계의 경과 시간은 거꾸로 가지 않는다.
