# signal-message-bus

`SIGUSR1`과 `SIGUSR2`를 0과 1로 사용해 같은 호스트의 두 프로세스 사이에서 문자열을 전달하는 POSIX C 프로그램입니다. 서버는 여덟 비트를 모아 바이트로 복원하고 NUL 바이트에서 메시지를 끝냅니다.

표준 시그널은 같은 종류의 여러 발생을 메시지 큐처럼 모두 보존하지 않습니다. 이 프로그램은 세션 예약과 비트별 확인 응답을 결합한 stop-and-wait 방식으로 한 번에 하나의 비트만 전송 중이도록 제한합니다. 예약과 응답은 로컬 Unix datagram 소켓을 사용합니다.

## 실행

```sh
make
./server
```

서버가 출력한 PID를 다른 터미널의 클라이언트에 전달합니다.

```sh
./client 12345 "hello"
```

빈 문자열도 NUL 프레임 하나로 전송하며 서버는 메시지마다 줄바꿈을 출력합니다.

## 전송 계약

1. 클라이언트가 응답 소켓을 만들고 무작위 nonce가 든 `ACQUIRE`를 보냅니다.
2. 서버가 송신 경로, PID와 세션 상태를 확인하고 `READY`를 보냅니다.
3. 클라이언트는 비트 하나를 시그널로 보냅니다.
4. 서버 시그널 처리기는 송신자 PID와 시그널 번호를 self-pipe에 기록합니다.
5. 이벤트 루프가 예약된 송신자의 비트를 조립하고, 완성된 바이트를 표준 출력에 기록합니다.
6. 출력까지 성공한 뒤 서버가 순번이 든 `ACK`를 보냅니다.
7. 클라이언트는 출처와 응답 필드를 확인한 뒤 다음 비트를 보냅니다.

예약과 비트 응답은 `CLOCK_MONOTONIC` 절대 기한을 사용합니다. 잘못된 datagram이나 `EINTR`가 와도 제한 시간이 새로 시작되지 않습니다.

예약·응답 datagram은 구조체 메모리를 그대로 보내므로 서버와 클라이언트는 같은
빌드와 ABI를 사용하는 로컬 쌍이어야 합니다. 서로 독립적으로 배포하거나 다른
아키텍처와 연결하는 프로토콜은 아닙니다.

## 런타임 경로와 권한

응답 소켓은 `/tmp/signal-message-bus-<uid>/` 아래에 만듭니다. 디렉터리는 현재 사용자 소유이고 그룹·기타 사용자 권한이 없어야 합니다. 같은 경로의 기존 항목은 현재 사용자 소유의 소켓일 때만 제거하며, 일반 파일이나 다른 사용자 소유 항목은 건드리지 않습니다.

## 검증

```sh
make test
```

실제 서버와 클라이언트를 실행해 일반·빈·UTF-8·장문 메시지, 세션 경쟁과 중단 복구, 응답 위조와 시간 초과, 데이터 시그널을 막은 상태로 실행한 클라이언트, 부분 쓰기와 `EINTR`/`EPIPE`, self-pipe 포화, stale socket 정리를 확인합니다.

프로토콜과 상태 전이는 [세션과 비트 프로토콜](architecture/session-and-bit-protocol.md), 시그널 처리와 응답 경계는 [이벤트 루프와 응답 검증](architecture/event-loop-and-response-validation.md)에 정리했습니다. 장애별 대응은 [개발 기록](devlog/README.md)에서 찾을 수 있습니다.

## 지원하지 않는 범위

- 다른 호스트나 다른 사용자 사이의 통신
- 같은 UID의 악성 프로세스를 구분하는 peer credential 인증
- 본문 안의 NUL 바이트
- 살아 있지만 영구 정지한 세션의 자동 만료
- 서버 재시작 뒤 세션 복구
- 데이터 시그널이 차단된 상태를 물려받은 서버 실행
- 프로토콜을 무시하고 연속으로 보낸 표준 시그널의 발생 횟수 보존
- 서로 다른 ABI나 프로토콜 버전으로 빌드된 실행 파일 사이의 통신

PID와 소켓을 확인한 직후 대상이 바뀌는 시간차와 PID 재사용 가능성도 남아 있습니다.
